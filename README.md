# 日股信用残分析工具 · Margin Analyzer

输入日本股票代码，查看信用买残、卖残、信用倍率、成交量消化日数，以及股价与杠杆持仓变化的关系。项目提供浏览器分析界面和一个轻量 Python 本地服务，用于辅助观察日股信用需给变化。

JPX 自 2026-09-28 起将「銘柄別信用取引残高」改为每个交易日公表全銘柄数据，本工具把它解析成可直接阅读的日次序列；本地服务存在的原因只有一个 —— JPX 的 PDF 受 CORS 限制，浏览器无法直连。

本工具**没有交易、下单或自动监控功能**，仅用于学习、研究与辅助观察。

## 核心功能

- **信息分层**：首页只回答「好坏 / 原因 / 轻重 / 关注点」四问，内部评分与算法解释全部下沉到详细页的折叠区。
- **信用需給 与 估值严格分离**：信用需給等级只使用信用交易自身指标；PER / PBR / EPS / BPS / 配当 一律不参与信用需給评分。
- **官方日次与周次回退**：自动模式优先连接本地 JPX 服务；不可用时回退 GananFinance 周次信用残，也可手动指定来源。
- **信用倍率分解**：展示买卖残、变化率及短期区间位置；绝对倍率标签与区间位置分别计算，不混为一谈。
- **买残消化日数**：按信用残最新日期截断完整行情，使用最后 20 个有效成交量记录计算，样本不足时明确降级。
- **股价 × 买残四象限**：观察上涨/下跌与买残增加/减少的组合，并提供规则解释。
- **分母可审计**：区分 Ganan 的发行股数与 JPX 的上市股份占比，显示来源、计算口径与可信度档位。
- **公司行动 fail-safe**：比较窗口内发生拆并股时停止方向判定，等级降为「判定不能」并在首页给出明确警示。
- **风险与方向分开**：规则引擎分别输出信用需给风险与方向倾向，并保留各自的触发原因。
- **概览与明细**：包含信用残趋势、价格对照、指标详情、估值参考及数据注意事项。
- **单文件成品可直接使用**：`日股信用残分析.html` 已内联 ECharts 与分析引擎，无需构建即可打开（获取行情与信用残仍需联网）。
- **可重复打包**：开发源码与单文件成品同时提交，支持检查成品是否与源码一致。

## 快速安装

### 运行要求

- Python **3.10 或更新版本**；服务依赖 `pdfplumber`，安装范围见 `requirements.txt`。
- 支持 JavaScript、Fetch 和现代语法的桌面浏览器，例如 Chrome、Edge、Safari。
- 联网访问 JPX、Ganan、Yahoo 及公共代理。
- 一键启动脚本面向 macOS / Bash 环境，端口检查使用 `lsof`；macOS 使用 `open` 自动打开浏览器。
- Node.js 18 或更新版本仅用于运行已有回归测试，日常使用和 Python 打包不需要。

### 手动安装

```bash
git clone https://github.com/tuffy-xie/margin-analyzer.git
cd margin-analyzer
python3 -m venv .venv
./.venv/bin/python3 -m pip install -r requirements.txt
./start.sh
```

脚本优先选择项目的 `.venv/bin/python3`，再选择 PATH 中的 `python3`；它只检查依赖，不自动安装。默认端口为 **8848**，已占用时依次尝试更高端口，以终端输出的地址为准。macOS 会自动打开浏览器，按 `Ctrl+C` 停止服务。

也可以直接指定端口：

```bash
./.venv/bin/python3 server.py 8848
```

然后打开 <http://127.0.0.1:8848>。服务只监听 `127.0.0.1`，定位为本机工具；当前实现没有远程部署所需的认证与访问控制。

### 直接打开单文件成品

双击 `日股信用残分析.html`，或将文件拖入浏览器。无需启动 Python 服务即可使用 Ganan 周次回退，但外部数据仍需联网；若本机 `8848` 端口有本项目服务，自动模式也会尝试连接官方通道。

从 `file://` 打开的成品使用固定本地 API 地址 `http://127.0.0.1:8848`：服务运行在其他端口时，请直接打开该端口的网页。

**推荐使用本地服务获取 JPX 官方日次数据。** 运行要求与其他启动方式见 [docs/TECHNICAL.md](docs/TECHNICAL.md)。

## 使用方法

1. 输入代码并点击「分析」；按 Enter 也可触发查询。
2. 根据需要选择「信用残：自动」「JPX 官方日次」或「Ganan 周次」。显式选择 JPX 时，官方通道失败会如实报错，不静默回退。
3. 先确认顶部的数据日期与实际来源，再看结论。首次查询可能需要下载并逐页解析多份 PDF，因此明显慢于缓存查询。
4. 结合消化日数、发行股数占比、买卖残变化和价格四象限阅读结果；不要只看倍率颜色。
5. 在「信用残詳細」检查分母口径、成交量窗口、样本数和异常提示；结论看起来意外时展开「判定ロジック」看评分构成。
6. 周次回退数据与官方日次数据的时间粒度不同，不要把两者直接横向比较。
7. 结论与直觉相反时，先看是不是公司行动（拆并股）或分母可信度不足导致的「判定不能」，再怀疑算法。
8. 想拿最新公表数据时点「刷新」：它会重新扫描 JPX 索引页；普通查询优先使用本地缓存，速度明显更快。

## 已知限制

- **拆并股不做数值修正**：只做 fail-safe（停止判定）。若某只股票在比较窗口内发生拆并股，但 Yahoo 未提供 `events`，且残量/价格特征不满足 fail-safe 条件，仍可能按真实变化处理。
- **阈值仍属启发式**：消化日数、倍率档位、四象限阈值、风险分权重均无行业统计标准，也没有经过历史回测校准。
- **20 日均量为简单算术平均**：极端爆量日会放大影响，未做稳健化处理。
- **窗口随源站而变**：前端请求最多 15 个官方记录，服务接口允许 1–40 个，但只遍历索引页当前可见的 PDF，不是完整历史数据库；历史不足时不会自动补齐长期序列。
- **分母时点不完全对齐**：Ganan 发行済株式数不带明确基准日期，与信用残日期不保证同步。
- **13 週趋势缺失**：当前程序尚未整合 JPX 旧周次历史数据。UI 的 13 周前比保持为空，不会用 13 天替代 13 周。
- **「判定不能」不是坏消息**：数据不足、公司行动命中或分母不可信时，本工具宁可给出 ⚪ 判定不能，也不会给出一个看起来漂亮但无依据的结论。
- **估值参考不是历史真实估值**：PER 区间以当前 EPS（普通界面可能由当前价格/预测 PER 推算）除历史价格重建，不是每个历史日期使用同期财报的真实历史 PER。
- **PBR 基准价通常不可用**：基准价与区间只允许使用已验证的财报 BPS，而当前 UI 未启用 J-Quants，页面可能显示推算 BPS 提示但该值不参与运算。
- **缺失与解析过滤**：零/非正买卖残、异常比值以及页面格式变更可能导致记录被过滤或查询失败，不保证覆盖所有股票、ETF、新股及极端状态。某个指标显示「—」是缺失，不是零值或低风险。
- **缓存无 TTL**：磁盘 JSON 缓存按「版本 + 来源指纹（PDF 大小/mtime）」校验，PDF 不变就不会重解析；JPX 修正历史数据后需手动 `fresh=1` 刷新。上游索引页有 TTL（普通请求 10 分钟、fresh 请求 2 分钟内同轮复用）。
- **上游依赖**：数据源和公共代理没有由本项目提供的可用性保证；错误、限流和缓存延迟均可能发生，最新页面价格不等于最新信用残日期的价格。

## Roadmap

- **13～26 周信用残趋势**：整合更长的信用残历史序列，补足目前只有日次短窗口的短板。
- **因子历史回测**：用历史数据校准消化日数、倍率档位与风险分权重，替代当前的启发式阈值。
- **批量扫描 / watchlist**：一次分析多只股票并按信用需给排序，便于日常筛票。
- **Discord / TradingAgents 输出**：把结论整理成可推送的简报，接入现有工作流。
- **异常变化提醒**：信用残或价格出现突变时主动提示，而不是只在手动查询时可见。
