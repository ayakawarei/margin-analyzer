# 日股信用残分析工具 · Margin Analyzer

输入日本股票代码，查看信用买残、卖残、信用倍率、成交量消化日数，以及股价与杠杆持仓变化的关系。项目提供浏览器分析界面和一个轻量 Python 本地服务，适合辅助观察日股信用需给变化。

## 核心特性

- **信息分层**：首页只回答「好坏 / 原因 / 轻重 / 关注点」四问，内部评分与算法解释全部下沉到详细页的折叠区。
- **信用需給 与 估值严格分离**：信用需給等级只使用信用交易自身指标；PER / PBR / EPS / BPS / 配当 不参与信用需給评分。
- **官方日次与周次回退**：自动模式优先连接本地 JPX 服务；不可用时回退 GananFinance 周次信用残，也可手动指定来源。
- **信用倍率分解**：展示买卖残、变化率及短期区间位置；绝对倍率标签与区间位置分别计算。
- **买残消化日数**：按信用残最新日期截断完整行情，使用最后 20 个有效成交量记录计算，样本不足时明确降级。
- **股价 × 买残四象限**：观察上涨/下跌与买残增加/减少的组合，并提供规则解释。
- **分母可审计**：区分 Ganan 的发行股数与 JPX 的上市股份占比，显示来源及计算口径。
- **风险与方向分开**：规则引擎分别输出信用需给风险和方向倾向，保留触发原因。
- **概览与明细**：包含信用残趋势、价格对照、指标详情、估值参考及数据注意事项。
- **可重复打包**：开发源码与单文件成品同时提交，支持检查成品是否与源码一致。

## 信息层级与评分作用域

### 首页（概要）—— 目标是 5 秒看懂

| 顺序 | 内容 | 说明 |
| --- | --- | --- |
| 1 | 股票名 / 代码 / 当前股价 | 顶部涨幅位刻意留空，避免与「同期比较」混淆 |
| 2 | 信用需給总判断 | 只给等级：🟢 改善 / 🟡 中立 / 🟠 注意 / 🔴 悪化 |
| 3 | 信用ポジション | 軽い / 普通 / 重い 三档文字，**不给数字** |
| 4 | 信用残同期股价・信用買残 | 两个事实，各只出现一次 |
| 5 | 三个核心 KPI | 買残消化日数 / 買残÷発行済比 / 信用倍率 |
| 6 | 一句结论 | 只讲形态与轻重，不复述已出现的百分比 |
| 7 | 👀 注目 | 下一步该看什么 |
| — | 股价 × 信用買残 单图 | 默认「変化率（初日=100）」，共用单 Y 轴 |

首页**不出现**：方向分 / 风险分等 0~100 内部量、每条规则的贡献值、触发规则明细。
同一事实在首页只出现一次（例如图下不再重复股价与买残的涨跌读数）。

### 信用需給 与 估值的边界

信用需給等级**只使用**以下信用交易自身指标：
株価×信用買残方向、信用買残变化、信用売残变化、買残消化日数、
買残÷発行済比 / 上場比、信用倍率。

**PER / PBR / EPS / BPS / 配当 / 估值区间一律不参与信用需給评分。**
估值高低不改变信用需給的好坏 —— 高估值股票不会因为「贵」被判成信用需給弱气。

### 詳細页结构

1. 信用買残 / 売残 / 倍率推移
2. 日次数据表
3. 消化日数の計算過程（可追溯到原始字段）
4. 上場比 / 発行済比 の詳細（分母口径与稳定性审计）
5. 信用需給核心指标总览
6. データ品質・異常検知
7. **この判定になった理由**（判定ロジック，默认折叠）
8. データ来源・公表时机 / 計算公式・口径

「判定ロジック」折叠区展开后显示方向分、信用风险分、每项贡献、触发规则，
以及被**排除**在评分之外的估值信号 —— 用于在首页结论看起来意外时做审计。

### 相关函数（`engine2.js`）

| 函数 | 用途 | 调用方 |
| --- | --- | --- |
| `creditVerdict(ind, vr)` | 只返回等级 + badge + 信用ポジション，**不返回数字分数** | 首页 |
| `creditPosition(ind)` | 仓位三档（軽い/普通/重い） | 首页 |
| `verdictAudit(ind, vr, val)` | 内部分数 + 规则贡献 + 被排除的估值信号 | 詳細页折叠区 |

```text

        │
        ▼
server.py ── pdfplumber ── .cache/（本地缓存）
        │
        └── /api/margin ──────────────┐
                                     ▼
Ganan / Yahoo ── 公共代理 ── engine.js ── index.html
                                     │       │
                                     ▼       ▼
                                  engine2.js / ECharts
                                     │
                                     ▼
                          概要、明细、指标与规则解释

index.html + 四个本地 JS ── build.py ── 日股信用残分析.html
                                             ▲
```

`official.js` 负责连接本地服务；`engine.js` 负责外部数据、基础解析和估值参考；`engine2.js` 负责信用指标、异常提示和评分规则；`index.html` 负责整合数据与渲染界面。

## 运行要求

- Python **3.10 或更新版本**；服务依赖 `pdfplumber`，安装范围见 `requirements.txt`。
- 支持 JavaScript、Fetch 和现代语法的桌面浏览器，例如 Chrome、Edge、Safari。
- 联网访问 JPX、Ganan、Yahoo 及公共代理。
- 一键启动脚本面向 macOS / Bash 环境，端口检查使用 `lsof`；macOS 使用 `open` 自动打开浏览器。
- Node.js 18 或更新版本仅用于运行已有回归测试，日常使用和 Python 打包不需要 Node.js。

## 安装与启动

### 推荐：本地服务

```bash
git clone https://github.com/tuffy-xie/margin-analyzer.git
cd margin-analyzer
python3 -m venv .venv
./.venv/bin/python3 -m pip install -r requirements.txt
./start.sh
```

脚本优先选择项目的 `.venv/bin/python3`，再选择 PATH 中的 `python3`；只检查依赖，不自动安装。默认端口为 **8848**，已占用时依次尝试更高端口，以终端输出的地址为准。macOS 会自动打开浏览器，按 `Ctrl+C` 停止服务。

也可以直接指定端口：

```bash
./.venv/bin/python3 server.py 8848
```

然后打开 <http://127.0.0.1:8848>。服务只监听 `127.0.0.1`，定位为本机工具；当前实现没有远程部署所需的认证与访问控制。

### 直接打开单文件

双击 `日股信用残分析.html`，或将文件拖入浏览器。无需启动 Python 服务即可使用 Ganan 周次回退，但外部数据仍需联网；若本机 `8848` 端口有本项目服务，自动模式也会尝试连接官方通道。

从 `file://` 打开的成品使用固定本地 API 地址 `http://127.0.0.1:8848`。如果服务运行在其他端口，请直接打开该端口的网页。

## 使用方法

1. 输入代码并点击「分析」；按 Enter 也可触发查询。
2. 根据需要选择「信用残：自动」「JPX 官方日次」或「Ganan 周次」。显式选择 JPX 时，官方通道失败会报错。
3. 确认数据日期与来源。首次查询可能需要下载、逐页解析多份 PDF，因此明显慢于缓存查询。
4. 结合消化日数、发行股数占比、买卖残变化和价格四象限阅读结果；不要只看倍率颜色。
5. 在明细页检查分母、成交量窗口、样本数和异常提示。

## 指标解释

| 指标 | 公式或逻辑 | 解读边界 |
| --- | --- | --- |
| 信用倍率 | `信用買残 ÷ 信用売残` | 倍率高可能由买残大或卖残少造成；单独不能判定涨跌或整体信用风险。 |
| 买残 / 卖残 | 内部原始单位为股；部分 UI 转换为万股（`÷ 10,000`） | 不同来源的频率、覆盖范围和股数口径应分别核对。 |
| 倍率绝对标签 | `<1` 売り長；`[1,3)` 均衡～良好；`[3,5)` やや高め；`[5,10)` 高め；`≥10` かなり高い | 这是当前代码的 UI 阈值，不是经过回测的预测结论；3、5、10 的边界归入后一档。 |
| 区间位置 | 当前倍率在已获取样本的最小值与最大值之间的位置 | 是当前样本窗口的相对位置；不能自动解释成中长期百分位。 |
| 买残消化日数 | `最新买残 ÷ 平均日成交量` | 只取 `date ≤ 最新信用残日期` 且 `volume > 0` 的记录，最后 20 个有效记录为主口径；5–19 个时降级为最后 5 个，少于 5 个不计算。不是实际平仓期限。 |
| 买残 / 发行股数 | `买残 ÷ Ganan 発行済株式数 × 100%` | 无发行股数时回退 JPX 上場比，分母变为上市股份；不能称为浮动股或流通股占比。 |
| 股价 × 买残四象限 | 同期价格变化与买残变化的组合 | 信用数据样本决定比较跨度，缺行情时可用性受限；仅是观察框架。 |
| 信用风险与方向 | `engine2.js` 中显式规则及权重相加并截断 | 风险范围 0–100，方向范围 −100 至 +100；没有胜率、概率或收益率含义，未经过历史回测校准。 |
| PER/PBR、配当 | 源站展示值；估值参考由引擎另行计算 | 页面指标可能属于不同更新时点，须区分站点值、推算值和财报实值。 |

## 数据口径与已知限制

- **日期不等于发布时刻**：JPX 数据行以申込日标识；Yahoo 代码以 UTC 格式化时间戳。当前价格对齐允许精确匹配及 `±1` 日候选（优先下一日），成交量行也有下一日回退。这是现有容错逻辑，在缺失日期时可能引入非同期数据；四象限不适合直接用于严格历史回测。消化日数另有截止日过滤，不使用此对齐序列。
- **窗口随源站而变**：前端请求最多 15 个官方记录，服务接口允许 1–40 个，但只遍历索引页当前可见 PDF，不是完整历史数据库。历史不足时不会自动补齐长期序列。
- **13 周比较**：当前 UI 整合路径没有注入周次历史比较，13 周前比保持为空，不用 13 天替代 13 周。底层遗留函数不代表页面已启用相应能力。
- **股数分母时点**：Ganan 发行股数没有在当前解析结果中携带明确基准日期，与信用残日期不保证一致；JPX 上場比仅作独立参考，不混称为发行股数或浮动股。
- **价格与公司行动**：读取 Yahoo `close` 与 `adjclose`，四象限优先使用 `adjclose`；JPX 买卖残股数尚未按拆并股统一调整。公司行动可能制造虚假的买卖残变化或风险评分，当前没有完整复权处理保证。
- **估值参考不是历史真实估值**：PER 区间以当前 EPS（普通界面可能由当前价格/预测 PER 推算）除历史价格重建；缺行情时有 `0.84×` / `1.84×` 当前 PER 的启发式回退。不是每个历史日期使用同期财报的真实历史 PER。
- **PBR 可靠性门槛**：PBR 基准价和区间只允许使用已验证的财报 BPS。当前 UI 没有启用 J-Quants，也没有传递财报验证状态，因此普通使用不应期待 PBR 基准价可用。页面可能显示推算 BPS 提示，但该值不参与 PBR 基准价运算。
- **缺失与解析过滤**：零/非正买卖残、部分异常比值以及页面格式变更可能导致记录被过滤或查询失败，不保证覆盖所有股票、ETF、新股及极端状态。
- **缓存与强制刷新**：服务按代码和请求长度保存进程内结果，并缓存 PDF 和 JSON。`fresh=1` 跳过内存缓存并重新读取索引，但不会删除或重解析既有磁盘缓存。健康接口可用也不等于所有标的都能完成解析。
- **上游依赖**：数据源和公共代理没有由本项目提供的可用性保证；错误、限流和缓存延迟均可能发生。最新页面价格不等于最新信用残日期的价格。

## 当前版本已知问题

信用需給评级仍需进一步审查：当日线缺失时，价格与买残可能使用不同的比较日期；消化日数和股数占比都不可用时，仓位档位可能仍显示「軽い」；发行股数来源不稳定时，其数值仍可能参与评分。拆并股造成的 JPX 股数变化没有统一调整，多线程服务的缓存写入也尚无并发保护。详细复现与建议见本次代码审查报告；使用评级前请核对详细页的原始数据、日期和分母。

```text
GET /api/margin?code=285A&days=15&fresh=1
```

健康接口只检查本地服务存活，成功时返回 `ok: true`、本地 PDF 缓存数量 `cached_pdfs` 和 `net: "not probed"`；它不访问 JPX，也不证明最新信用残可用。查询接口返回原始股数、日期、倍率及来源，例如：

```json
{
  "ok": true,
  "code": "7974",
  "name": "任天堂",
  "rows": [
    { "date": "2026-10-01", "sell": 703700, "buy": 9145500, "ratio": 13.0 }
  ],
  "count": 1,
  "latest": "2026-10-01",
  "fresh": false,
  "source": "JPX 官方「銘柄別信用取引残高」（每交易日 16:00 公表）"
}
```

上例用于说明响应结构，不代表实时查询结果；额外字段以实际响应为准。要验证 JPX 数据链路，需要实际调用 `/api/margin` 并检查返回的日期与行数。

## 开发、测试与打包

修改 `index.html`、`engine.js`、`engine2.js` 或 `official.js` 后重新打包：

```bash
python3 build.py
python3 build.py --check
node test_digest.mjs
node test_ratio.mjs
node test_audit.mjs
node test_audit2.mjs
node test_layer.mjs
```

`build.py` 使用字面量替换内联本地脚本，避免打包时改变 JavaScript 中的美元符号；`--check` 只检查一致性，不写文件。无需 npm 或前端构建依赖。

已有 JavaScript 测试使用构造数据验证消化日数、倍率、分母及信息层级。`test_parse.py` 固定使用本地 `.cache/20261002_mtall.pdf` 进行 PDF 回归；该缓存未随仓库分发，缺失时会明确显示 `SKIP`。`verify_ui.py` 是本机浏览器检查脚本，会输出观察结果，当前不会自动判定验收失败。通过这些测试不代表上游抓取、PDF 全字段或整个算法均已完成审计。

本地服务的 `/` 与 `/index.html` 都提供成品 HTML，**不会单独提供开发版 JS 静态文件**。修改后应重新打包再刷新。也可直接在浏览器打开开发版 `index.html`，它会引用同目录 JS 并尝试固定 `8848` 端口的 API。

## 常见问题

**查询首次很慢**：下载与逐页解析 PDF 耗时，换代码也可能触发解析。前端官方通道有有限重试，先确认本地服务日志，避免连续重复查询。

**官方源不可用**：确认服务已启动且地址/端口正确；直接打开文件时只探测固定 `8848`。自动模式可能改用 Ganan，务必检查来源提示。

**页面数据没有更新**：JPX 索引可能尚未发布新文件；可请求 `fresh=1` 或重启服务刷新内存结果，但磁盘文件仍会复用。

**某个指标显示「—」**：可能是样本、成交量、发行股数或验证后的 EPS/BPS 缺失。不要把缺失当作零值或低风险证明。
